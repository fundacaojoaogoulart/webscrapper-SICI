# Setup-ci: opt-in GitHub Actions

- Determinar primeiro se há `.github/workflows/`. Se ausente, perguntar literalmente: “Foi identificado que ainda não existe CI nesse projeto, deseja implementar um CI com GitHub Actions?”; aguardar aprovação antes de criar o workflow. Se existente, inspecionar triggers, permissões e deploys; pedir autorização antes de acrescentar job ou novo workflow, sem sobrescrever existente.
- CI suportado neste kit: GitHub Actions. Somente triagem + build/validação como padrão. Copiar `templates/documentation.yml` APENAS após autorização, adaptar base branch, dependências, políticas de PR e eventuais conflitos no projeto.
- Workflow gera `.docs-update/review-context.json` e `.docs-update/result.json` como artefato. `review_ai` não representa documentação automaticamente atualizada. Definir política de sinalização de pendência aprovada pelo usuário (não bloquear CI arbitrariamente).
- Opção IA requer aprovação explícita e credenciais/modelo configurados (`DOCS_AI_MODEL`, segredo de provider). O template executa AI apenas `workflow_dispatch` com `run_ai=true`; jamais no PR, especialmente PR de fork. OpenCode precisa estar disponível no PATH (template o instala com npm); escolher modelo compatível. Manter permissões mínimas do GitHub token; nunca commitar alterações automaticamente. Exportar proposta como artefato patch para revisão. Verificar a compatibilidade da versão instalada do OpenCode; preferir fixar versão após teste.
- CLI local `docs-update.py update` NÃO invoca OpenCode. Se necessário, o agente executa manualmente com contexto; documentar isso no README do projeto e `documentation-maintenance.md`.
